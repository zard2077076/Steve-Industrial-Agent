## 最终形态

玩家给出产物、产量或目标库存、场地与预算，Agent 利用真实配方规划工业产线，展示可读的
材料与布局预览；在玩家授权范围内清场、预留取料、用真实 Bot 搭建和调试，验证真实产出，
精确结算并长期维护。普通模式简洁易用，高级模式提供配方、物流、能源、风格和规模选择。

后台应支持 Create、IE 及逐步接入的其他工业 Mod，统一材料/流体/能源、仓库、任务调度、
跨进程恢复和维护诊断。扩建、多层工厂、移动工厂等远期目标保留，不用占位接口假装已实现。
游戏内核能、辐射或军需能力不涉及现实操作知识；高风险游戏自动化仍需独立的范围与安全设计。

## 已实现的能力

以下是能力摘要，不表示每种产品、环境和故障组合都经过实机验证。详细历史可通过
`git show cbac708:docs/PROJECT_STATE.md` 查看，不再在工作树复制一份完整归档。

- 真实配方发现、派生目标、逻辑/物理规划、材料需求与权限边界；玩家终端支持搜索、选址、
  预览、推荐位置、清场授权、回收箱和材料箱选择。
- `ProjectMaterialLedger` 与独立 `SalvageLedger`：按身份和数量预留、事务型扣取/返还、
  显式回收物转账、持久化对账；不能静默换箱、拿私人物品或凭空补偿。
- Create 的 milling/pressing/crushing/splashing/cutting/mixing/compacting/deploying，
  以及 smoking/haunting/blasting 有分层物理证据。C-01/02 是发现与动能基础；
  C-03～C-10 的生存动力已实现，不能再按旧文档说“尚无映射”。
- DIRECT/BOTS/HYBRID 共享计划与材料结果；已实现多 Bot 分工、带上下台阶的有界导航、
  线性和分支合并 Composite。安全取消测试的 Composite-02 不等于普通并行工厂产品。
- IE Metal Press 真实成型、热电/LV 供电、单批 2400 FE、唯一铁板、模具返还与拆除；
  Alloy Smelter 的物品燃料生产和玩家/仓库接线已有服务器证据。
- 物品/流体/能源发现、真实流体转账与管道拓扑、仓库多源、搬运、常驻、库存维持和重启恢复；
  只读诊断与经授权的有限维护已有实现，并非“只有决策、不生产”。
- Mekanism 当前只有可选缺席处理和化学资源/能力契约；不能声称真实机器已接入。
- Mac 真实客户端已跑过终端/搜索、C-03、Metal Press、Composite/01，范围见当前状态。
  C-04 双进程恢复超时已修复，不能继续作为开发阻塞。

## 必须清楚的边界

- 当前开发/验收仍只操作指定的隔离测试环境，不把正式玩家实例当试验场。
- 目录数量、某次 suite 的测试数、机器放置数是有版本和输入的观测值，不是永恒常量。
  产品搜索验证当前目录的内容、来源、可用性和下单能力；不要硬守“200/311/434”旧总数。
- 配方与事务的精确数量有实际含义，应验证来源与守恒。更换测试写法不等于允许多扣取、
  重复产出或把失败改成通过。
- 不确定的执行中断应按真实持久化证据恢复或安全返还；已有支持与未覆盖窗口分开说明。
  不把旧“不可恢复”结论扩大为禁止改进，也不宣称任意 PROCESS 中断都能恢复。
- 协议和架构可以演进，但持久化/网络兼容变更须处理版本、迁移和旧存档，不以“冻结”拒绝
  必要改进，也不无声破坏现有用户数据。

## 已知陷阱（按需查阅）

- 共享竞技场可能互相污染；粉碎轮等会破坏邻居。按真实影响隔离，而非每个测试必起新服务器。
- `FakePlayer` 不等于在线玩家；无玩家/forced chunks 的原版世界 300 tick 后会跳过实体/BE
  dispatch。`positionTicking=true` 不能证明机器实际调用了 tick。
- 掉落物 UUID 会因原版合并消失；必须追踪物品守恒，不以 UUID 消失判定丢失。
- 预留按物品身份/数量生效，整理箱内槽位不应失效；原版漏斗选槽顺序是另一种物理语义。
- 状态时间序列、控制流和世界实物优先于猜测；使用旧日志时检查版本和结果日期。
- 只读 UI/目录快照不能授予执行权限；报告必须绑定本订单，而非碰巧数量相同的旧报告。
- 已完成的精确细节、旧实验和全部原条目可用 `git show cbac708:docs/MASTER_PLAN.md`
  查看，不必每次从头重读。

## 验证选择

开发按玩家流程交付，而不是按模块数量推进：先完成当前失败的材料预览/预留路径，再扩大
代表性产品，接着补取消/恢复和多 Bot。复现 → 共享原因修复 → 受影响验证 → 可用环境中的
真实玩家确认；已有能力优先复用，不为测试再造一套材料算法。小步定位期间跑相关检查，
涉及共享材料/执行契约时再跑集成套件；未变的结果按 AGENTS 的条件复用。

迭代用相关 JVM 测试；改真实机器/资源/恢复时增加相应服务器物理测试；交互用真实客户端。
命令入口见 [HANDOFF_CODEX](HANDOFF_CODEX.md)。选择风险相关覆盖，不因改一行文案自动跑
全套发布验证；也不以一个单元测试代替真实材料与跨进程验证。
