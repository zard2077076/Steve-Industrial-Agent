# Player-world safety

## Current boundary

PW-01 through PW-10 classify exact world/game/save/runtime identity, apply explicit limits, fail closed at every mutation entry, produce deterministic preview/risk/budget evidence, compare region/approval scope, provide isolated-only verified backup and normalize claim decisions through a generic Adapter boundary. None constructs readiness or a write permit. Formal player worlds, unknown worlds and configured forbidden roots are never writable or executable. Directory names, a claimed enum, any report/check/token/backup/permission result, a session, recovery checkpoint or journal cannot grant authority.

The exact Create 6.0.6 implementation resolves the current real game directory, configured forbidden root, server world root and repository-created marker before every handler invocation, ITEM-route placement, resource-buffer change and rollback restore. If any proof changes after session construction, the next write attempt returns `FORMAL_WORLD_EXECUTION_FORBIDDEN` and does not mutate the target.

The formal external instance remains read-only. No formal save has been opened, scanned, backed up or started by this phase. PW-11 aggregates twenty-five independently typed readiness checks and can produce only an isolated, data-only `DeploymentReadyPlan`; it adds no session or mutation authority. PW-12 adds only read-only command acceptance and does not broaden that authority. PW-10 discovered OPAC only from retained disposable evidence and did not call its API; UNKNOWN remains blocking.

## Non-equivalence rules

- Classification is not permission.
- A dry-run is not approval.
- Approval is not execution authority.
- A backup plan is not a completed backup.
- A recovered session is not permission to resume.
- TEST_ONLY evidence is never valid for a formal player world.

## PW-12 command acceptance

PW-12 exposes preview, risks, budget and readiness strictly as dry-run command reports, with formal execution, world mutation, sessions, item consumption, machine starts, LLM calls and free-text coordinates fixed false. The accepted runs use only the repository-owned Create-only server and disposable DeceasedCraft profile. The custom pack matrix covers actual milling and pressing targets, three orientations and all four views; external fingerprints remain unchanged, formal saves remain unread, crash reports are zero and residual Java processes are zero. A successful command means only that a complete report was produced; readiness remains BLOCKED.
